# VS版本施工清单

## 一、文档定位

本文档是 `VS版本` 的程序施工清单，来源于 `Docs/总设计文档/VS版本计划规划.md`。

本文档只描述技术实施顺序、目录落点、迁移任务、验证方式和禁止事项，不扩展玩法设计和数值设计。

## 二、施工目标

`VS版本` 的施工目标是完成一个可运行的俯视角基础战斗验证场景：

```text
Assets/Game/Tests/Combat/TestCombat.unity
```

该场景必须能验证：

1. 玩家可以在平面上移动。
2. 摄像机可以稳定俯视角跟随玩家。
3. 鼠标可以控制基础瞄准方向。
4. 玩家可以使用一把基础武器开火。
5. 武器可以命中基础怪物。
6. 怪物可以扣血并死亡。
7. 基础怪物可以追踪并接近玩家。
8. HUD 可以显示血量、弹药和准星。
9. 场景不依赖 `Assets/ProjectRef`。
10. 从参考 Demo 复制来的内容必须完成项目原创命名。

## 三、施工来源与边界

### 3.1 可用来源

| 来源 | 用途 |
|---|---|
| `Docs/总设计文档/VS版本计划规划.md` | VS 版本目标、模块范围、测试场景位置和验收标准。 |
| `Docs/程序文档/TopDownDemo完整技术拆解.md` | 识别 TopDownDemo 中可迁移的摄像机、瞄准、开火、命中、HUD、生命和反馈思路。 |

| `Assets/ProjectRef` | 只作为复制迁移来源，不能作为正式运行依赖。 |

### 3.2 施工边界

1. 不在 `Assets/ProjectRef` 内开发正式功能。
2. 不让 `Assets/Game` 下的正式内容引用 `Assets/ProjectRef`。
3. 不直接继承模板巨型角色控制器、全能背包、混合 UI 根节点、静态全局管理器、复杂 TPS 巡逻 AI 和车辆系统。
4. 不做基地、仓库、撤离、搜打撤、生存、成长、任务、人类据点和三方冲突。
5. 不创建正式 `Assets/Game/Scenes` 下的测试场景。
6. 临时测试代码放入 `Assets/TmpTests`，正式 VS 运行内容放入 `Assets/Game`。

## 五、命名规则

### 5.1 命名空间

正式代码必须使用当前项目命名空间，优先使用：

```text
CZ.Player
CZ.Camera
CZ.Weapons
CZ.Ballistics
CZ.HitDetection
CZ.Enemies
CZ.UI
CZ.CombatFeedback
```

### 5.2 禁止命名

正式迁移内容不能保留以下参考项目命名作为业务命名：

1. `JU`
2. `JUTPS`
3. `Julhiecio`
4. `TopDownDemo`
5. 原模板 Prefab 名称。
6. 原模板脚本名称。
7. 原模板命名空间。

### 5.3 推荐命名方向

| 内容 | 推荐命名方向 |
|---|---|
| 玩家控制 | `PlayerMotor`、`PlayerAimController`、`PlayerCombatController` |
| 摄像机 | `TopDownCameraRig`、`CameraFollowTarget` |
| 武器 | `BasicWeaponController`、`WeaponRuntimeState` |
| 弹道 | `ProjectileMover`、`BulletProjectile` |
| 命中 | `HitResolver`、`DamageReceiver` |
| 怪物 | `BasicInfectedEnemy`、`EnemyChaseController` |
| HUD | `CombatHudView`、`HealthHudView`、`AmmoHudView`、`CrosshairView` |
| 反馈 | `CombatFeedbackPlayer`、`HitFeedbackSpawner` |

## 七、阶段一：迁移候选梳理

### 7.1 施工内容

本阶段的开发与记录必须严格参考 `Docs/程序文档/VS版本阶段一迁移候选清单.md`，并将该文档作为阶段一最终基线。

1. 根据 `TopDownDemo完整技术拆解.md` 列出 VS 可用内容。
2. 标记哪些内容可以复制资源，哪些内容只能参考思路。
3. 为每个可复制内容确定 `Assets/Game` 目标目录。
4. 为每个可复制内容确定项目原创命名。
5. 排除所有不进入 VS 的模板内容。

### 7.2 可优先迁移候选

| 候选内容 | 迁移方式 | 目标用途 |
|---|---|---|
| 俯视角摄像机参数和 Prefab 结构 | 复制后改名或按思路重建 | 快速搭建俯视角跟随。 |
| 鼠标射线瞄准思路 | 按当前项目命名重写 | 实现鼠标世界瞄准。 |
| 单武器开火链路 | 拆出最小逻辑重写 | 验证基础射击。 |
| 子弹忽略发射者思路 | 按当前项目重写 | 避免打中自己。 |
| 准星 UI 表现资源 | 复制后改名 | 快速显示准星。 |
| 血条和弹药 UI 表现资源 | 复制后改名 | 快速显示 HUD。 |
| 基础枪口火焰和命中特效 | 复制后改名 | 快速形成开火反馈。 |
| 灰盒地面、障碍、靶子摆放思路 | 复制或重建 | 搭建 `TestCombat`。 |

### 7.3 禁止迁移对象

1. 模板巨型角色控制器。
2. 模板全能背包。
3. 模板混合 UI 根节点。
4. 模板静态全局管理器。
5. 模板车辆驾驶系统。
6. 模板复杂 IK 系统。
7. 模板完整换枪系统。
8. 模板 TPS 巡逻 AI。

### 7.4 验证清单

1. 候选清单中每项都有目标目录。
2. 候选清单中每项都有新命名。
3. 候选清单中没有保留模板业务命名。
4. 候选清单没有把 `Assets/ProjectRef` 作为运行路径。

## 八、阶段二：创建 TestCombat 测试场景

本阶段创建 `TestCombat.unity` 时，凡涉及灰盒资源、摄像机参数、占位武器、UI 素材和测试对象选择，都必须严格参考 `Docs/程序文档/VS版本阶段一迁移候选清单.md`。

2. 场景中放置基础地面、边界、玩家出生点、怪物出生点和测试障碍。
3. 场景只服务 VS 验证，不作为正式地图。
4. 场景中不引用 `Assets/ProjectRef` 资源。

### 8.2 场景最低构成

| 场景内容 | 用途 |
|---|---|
| 基础地面 | 提供玩家和怪物移动平面。 |
| 边界或墙体 | 避免玩家离开测试区域。 |
| 玩家出生点 | 放置玩家预制体。 |
| 怪物出生点 | 放置或生成基础怪物。 |
| 摄像机 | 验证俯视角跟随。 |
| HUD | 验证血量、弹药、准星。 |

### 8.3 验证清单

1. `TestCombat.unity` 位于 `Assets/Game/Tests/Combat`。
2. `Assets/Game/Scenes` 下没有测试场景。
3. 场景命名符合测试场景目录规则。
4. 场景可以在 Unity 中打开。

## 十三、阶段七：引用清理与 VS 验收

### 13.1 施工内容

本阶段进行引用清理和验收时，必须严格参考 `Docs/程序文档/VS版本阶段一迁移候选清单.md`，逐项检查目标目录、原创命名、禁止迁移对象和 `Assets/ProjectRef` 运行依赖。

1. 检查 `Assets/Game` 下是否仍引用 `Assets/ProjectRef`。
2. 检查正式代码是否仍包含模板命名空间或模板业务前缀。
3. 检查 `TestCombat.unity` 是否能独立运行。
4. 检查 VS 交付物是否齐全。
5. 按验收标准验证一到三分钟基础战斗。

### 13.2 引用清理检查

需要检查以下内容：

1. `Assets/Game` 下没有运行时依赖 `Assets/ProjectRef`。
2. `Assets/Game` 下正式脚本不使用模板命名空间。
3. `Assets/Game` 下正式资源不保留模板 Prefab 名称。
4. `TestCombat.unity` 不引用参考 Demo 场景对象。
5. 复制迁移的资源已经进入正式目录或测试场景目录。

### 13.3 VS 验收清单

1. 玩家移动是否顺手。
2. 鼠标瞄准是否清楚。
3. 开火反馈是否明确。
4. 武器是否能命中怪物。
5. 怪物是否能追踪玩家。
6. 怪物是否能扣血死亡。
7. HUD 是否显示生命、弹药和准星。
8. 场景是否不依赖 `Assets/ProjectRef`。
9. 复制迁移内容是否完成项目原创命名。
10. 一到三分钟战斗是否值得进入 `FVS版本`。

## 十四、禁止事项

1. 禁止把 `Assets/ProjectRef` 当作正式运行依赖。
2. 禁止在 `Assets/ProjectRef` 内开发 VS 正式功能。

## 十六、后续衔接

`VS版本` 通过验收后，才进入 `FVS版本`。

`FVS版本` 的主要扩展方向是：

1. 增加二到三把基础武器。
2. 增加二到三种怪物。
3. 增加基础刷怪节奏。
4. 增加基础掉落和拾取。
5. 增加更明显的血腥反馈和战斗反馈。
6. 验证五到十分钟连续战斗是否有爽感。
