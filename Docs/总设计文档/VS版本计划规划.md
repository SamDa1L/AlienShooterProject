# VS版本计划规划

## 一、文档定位

本文档用于说明 `VS版本` 的总体计划、阶段目标、模块范围、模块之间的连接关系、交付物和验收标准。

本文档属于总设计文档，只描述 `VS版本` 需要完成哪些顶层模块，以及这些模块如何组成一个可验证的最小体验。不写具体代码结构、接口设计、施工步骤，也不写详细数值和具体玩法参数。

## 二、版本定位

`VS版本` 是当前项目的第一个基础验证版本。它不是完整 Demo，不是 MVP，也不是可公开试玩版本。

`VS版本` 的核心目的只有一个：验证俯视角人物移动、基础瞄准、基础射击、基础打怪和基础操作手感是否成立。

如果 `VS版本` 的移动、瞄准、射击、命中和打怪不顺手，后续搜打撤、基地、仓库、生存、成长、据点和任务都不应继续扩大制作范围。

## 三、版本目标

`VS版本` 必须完成以下目标：

1. 完成俯视角玩家移动。
2. 完成鼠标瞄准或基础朝向控制。
3. 完成基础射击。
4. 完成一种基础怪物追踪玩家。
5. 完成基础命中、扣血和死亡。
6. 完成基础玩家血量和弹药显示。
7. 完成一个灰盒战斗测试场景。
8. 验证一分钟到三分钟的战斗是否顺手。

## 四、核心体验闭环

`VS版本` 的体验闭环必须极短，目标是快速验证手感。

```text
进入测试场景
-> 玩家移动
-> 鼠标瞄准
-> 开枪射击
-> 子弹或射线命中怪物
-> 怪物扣血死亡
-> 怪物继续刷新或场上保留压力
-> 玩家观察血量、弹药和准星反馈
-> 重复移动、瞄准、射击、打怪
```

这个闭环不包含搜刮、撤离、仓库、基地、任务、成长和生存压力。

## 五、需要完成的模块总览

| 模块 | VS版本职责 | 输出结果 |

## 六、模块连接关系

### 6.1 运行入口连接

```text
启动项目
-> 进入 VS 测试场景
-> 初始化玩家、摄像机、怪物、HUD
-> 开始基础战斗验证
```

运行入口只需要服务当前版本验证，不需要完整主菜单、读档、基地和地图选择。

### 6.2 玩家操作连接

```text
玩家输入
-> 玩家移动模块
-> 玩家角色在灰盒场景中移动
-> 摄像机跟随玩家
```

这一条连接用于验证俯视角移动是否顺手，重点是方向清楚、移动响应及时、镜头不干扰操作。

### 6.3 瞄准射击连接

```text
鼠标位置
-> 基础瞄准模块
-> 玩家朝向或武器朝向更新
-> 基础武器模块执行开火
-> 基础命中模块判断命中
```

这一条连接用于验证玩家是否能准确理解瞄准方向，以及开火是否能得到清晰反馈。

### 6.4 怪物战斗连接

```text
怪物生成或放置在场景中
-> 基础怪物模块追踪玩家
-> 玩家射击怪物
-> 怪物生命模块扣血
-> 怪物死亡
-> 基础反馈模块播放死亡反馈
```

这一条连接用于验证“移动躲怪、瞄准开枪、击杀怪物”的最小战斗循环。

### 6.5 HUD 反馈连接

```text
玩家生命变化
-> HUD 显示血量

武器弹药变化
-> HUD 显示弹药

瞄准状态变化
-> HUD 显示准星
```

HUD 只展示 `VS版本` 必需信息，不做背包、任务、地图、撤离、仓库和成长界面。

## 七、模块范围说明

### 7.1 版本启动模块

需要完成：

1. 可以直接进入 VS 战斗测试场景。
2. 可以快速重复测试移动、瞄准、射击和打怪。
3. 不依赖完整主菜单和完整存档流程。

不需要完成：

1. 正式主菜单。
2. 正式加载界面。
3. 账号、云存档或多存档位。

### 7.2 灰盒测试场景模块

需要完成：

1. 一个基础平面战斗区域。
2. 简单障碍物或边界。
3. 玩家出生点。
4. 怪物出生点或怪物放置点。
5. 足够验证一分钟到三分钟战斗的空间。

不需要完成：

1. 正式农场地图。
2. 正式美术布景。
3. 资源点、撤离点和据点布局。

### 7.3 玩家基础控制模块

需要完成：

1. 玩家在平面上移动。
2. 移动方向符合俯视角直觉。
3. 移动响应及时。
4. 移动和瞄准能同时进行。

不需要完成：

1. 翻滚。
2. 冲刺。
3. 蹲伏。
4. 复杂体力消耗。
5. 复杂受击硬直。

### 7.4 俯视角摄像机模块

需要完成：

1. 摄像机稳定跟随玩家。
2. 玩家、怪物和战斗空间保持可见。
3. 镜头高度和角度适合俯视角战斗。
4. 不因玩家移动产生明显眩晕或抖动。

不需要完成：

1. 完整镜头状态机。
2. 室内外复杂遮挡。
3. 剧情镜头。
4. 多镜头切换。

### 7.5 基础瞄准模块

需要完成：

1. 鼠标位置能表达瞄准方向。
2. 玩家朝向或武器朝向能跟随瞄准方向。
3. 准星能辅助玩家理解瞄准点。
4. 移动时仍能瞄准。

不需要完成：

1. 手柄完整适配。
2. 自动瞄准。
3. 锁定目标。
4. 开镜和瞄具系统。

### 7.6 基础武器模块

需要完成：

1. 一把基础武器。
2. 基础开火。
3. 基础射速限制。
4. 基础弹药显示。
5. 能对怪物造成伤害。

不需要完成：

1. 多武器切换。
2. 复杂换弹。
3. 配件改装。
4. 武器稀有度。
5. 武器熟练度。

### 7.7 基础命中模块

需要完成：

1. 判断玩家攻击是否命中怪物。
2. 命中后怪物扣血。
3. 命中时有基础反馈。
4. 怪物死亡时有基础死亡反馈。

不需要完成：

1. 部位伤害。
2. 护甲穿透。
3. 元素伤害。
4. 复杂暴击系统。
5. 友伤系统。

### 7.8 基础怪物模块

需要完成：

1. 一种基础怪物。
2. 怪物能发现并追踪玩家。
3. 怪物能靠近玩家形成压力。
4. 怪物能被击杀。

不需要完成：

1. 多怪物类型。
2. 精英怪。
3. Boss。
4. 人类敌人。
5. 复杂群体战术。

### 7.9 基础生命模块

需要完成：

1. 玩家有生命值。
2. 怪物有生命值。
3. 怪物生命归零后死亡。
4. 玩家生命可以显示在 HUD 上。

不需要完成：

1. 正式死亡惩罚。
2. 复活规则。
3. 受伤状态。
4. 生存负面状态。

### 7.10 基础 HUD 模块

需要完成：

1. 玩家生命显示。
2. 当前弹药显示。
3. 基础准星显示。
4. 必要的最小提示信息。

不需要完成：

1. 背包界面。
2. 仓库界面。
3. 任务界面。
4. 地图界面。
5. 角色成长界面。
6. 结算界面。

### 7.11 基础反馈模块

需要完成：

1. 开火反馈。
2. 命中反馈。
3. 怪物死亡反馈。
4. 最小音效或视觉提示。

不需要完成：

1. 完整血腥反馈系统。
2. 断肢表现。
3. 大量血迹持久化。
4. 复杂屏幕特效。

## 八、不进入 VS版本的内容

以下内容明确不进入 `VS版本` 范围：

1. 防空洞基地。
2. 搜打撤完整流程。
3. 仓库系统。
4. 背包系统完整规则。
5. 撤离系统。
6. 警戒值系统。
7. 人类据点系统。
8. 三方冲突系统。
9. 人类敌人 AI。
10. 饥饿、口渴、疲劳。
11. 局内物品使用。
12. 人物成长。
13. 武器熟练度。
14. 枪械改装。
15. 任务系统。
16. 地图推进。
17. 正式美术资源。
18. 正式音频资源。
19. Steam 页面和商业化内容。

## 九、测试场景规划

`VS版本` 的测试场景应放在测试场景目录中，不放在正式场景目录中。

建议场景位置：

```text
Assets/Game/Tests/Combat/TestCombat.unity
```

测试场景需要承载：

1. 玩家出生点。
2. 基础摄像机。
3. 基础怪物生成或摆放点。
4. 基础战斗空间。
5. 基础 HUD。
6. 基础障碍物或边界。

测试场景不要求达到正式地图美术质量。

## 十、TopDownDemo 迁移加速规划

`TopDownDemo完整技术拆解` 已经证明参考 Demo 中存在一套可运行的俯视角射击链路。`VS版本` 可以利用这套参考内容加速完成，但必须遵守以下原则：

1. `Assets/ProjectRef` 只能作为迁移来源，不能作为正式运行依赖。
2. 能直接使用的内容必须复制到 `Assets/Game` 下对应正式目录。
3. 复制后的文件、资源标题、Prefab 名称、脚本名称和命名空间必须按当前项目原创命名规则重命名。
4. 正式内容不能保留模板项目的命名体系，不能继续使用模板业务前缀作为正式项目命名。
5. 巨型控制器、全能背包、混合 UI 根节点、静态全局管理器、复杂 TPS AI 和车辆高耦合逻辑不能直接继承为正式架构。

### 10.4 VS版本迁移后的模块串联

利用 TopDownDemo 加速后，`VS版本` 的目标链路应调整为：

```text
复制可用参考内容
-> 按当前项目命名规则重命名
-> 放入 Assets/Game 正式目录
-> 在 Assets/Game/Tests/Combat/TestCombat.unity 中组合验证
-> 玩家移动
-> 摄像机跟随
-> 鼠标瞄准
-> 单武器开火
-> 命中怪物
-> 怪物扣血死亡
-> HUD 显示血量、弹药、准星
-> 得出 VS 版本是否成立的结论
```

### 10.5 迁移边界

`VS版本` 允许为了快速验证手感，先使用从 Demo 复制并重命名后的占位资源。但这些资源一旦进入 `Assets/Game`，就必须被视为当前项目正式资源或正式测试资源，不能再保留对 `Assets/ProjectRef` 的引用。

如果某个资源只是临时测试代码或临时辅助工具，应放入 `Assets/TmpTests`。如果它是 `TestCombat.unity` 场景实际使用的测试场景资源，应放入 `Assets/Game/Tests/Combat` 或对应正式模块目录。

## 十一、交付物

`VS版本` 交付物如下：

1. 一个可运行的俯视角战斗测试场景。
2. 一个玩家角色。
3. 一把基础武器。
4. 一种基础怪物。
5. 一个基础 HUD。
6. 一套基础操作输入。
7. 一套基础命中、扣血和死亡反馈。
8. 一个可以重复验证一分钟到三分钟战斗体验的测试环境。

9. 从 TopDownDemo 复制迁移并重新命名后的最小可用正式资源。
10. 不依赖 `Assets/ProjectRef` 的 `TestCombat.unity` 验证场景。

## 十二、验收标准

`VS版本` 必须回答以下问题：

1. 玩家移动是否顺手？
2. 鼠标瞄准或基础朝向是否清楚？
3. 玩家是否能直观看懂自己正在瞄准哪里？
4. 开枪是否有明确反馈？
5. 武器是否能稳定命中怪物？
6. 怪物是否能追踪玩家并形成最低压力？
7. 怪物被击中、扣血、死亡是否清楚？
8. 玩家生命、弹药和准星是否足够表达当前状态？
9. 一分钟到三分钟的战斗是否顺手？
10. 这个基础战斗是否值得进入 `FVS版本` 扩展？

只有以上问题大部分都能回答“是”，项目才进入 `FVS版本`。

11. 正式验证场景是否已经不依赖 `Assets/ProjectRef`？
12. 从参考 Demo 复制来的内容是否已经完成项目原创命名？

## 十三、进入 FVS版本的条件

`VS版本` 通过后，才能进入 `FVS版本`。

进入条件：

1. 玩家移动、瞄准和射击手感成立。
2. 基础怪物追踪和击杀循环成立。
3. 基础 HUD 信息足够清楚。
4. 战斗测试场景能稳定运行。
5. 没有阻断继续扩展的核心操作问题。

`FVS版本` 的主要任务是在此基础上增加多武器、多怪物、基础掉落、基础血腥反馈和更长战斗节奏验证。

## 十四、总结

`VS版本` 是项目最小可验证版本，它只验证俯视角射击游戏最核心的手感：移动、瞄准、射击、命中、打怪和基础 HUD。

TopDownDemo 可以显著加速 `VS版本`，但只能作为复制迁移来源，不能作为正式依赖。这个版本越收敛越好。只要基础战斗不成立，后续所有搜打撤、生存、成长、据点、任务和商业化内容都没有继续扩大的价值。
